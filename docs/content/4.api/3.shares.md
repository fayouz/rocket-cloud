Les liens de partage appartiennent à l'utilisateur qui les crée : un JWT, ou une application qui impersonne un utilisateur. Voir [Authentification](/api/authentication).

## Créer un lien

`POST /api/shares`, en JSON, avec **soit** `file`, **soit** `folder` :

| Champ | Rôle | Défaut |
|---|---|---|
| `file` | Fichier partagé (`/api/files/<id>`) | — |
| `folder` | Dossier partagé (`/api/folders/<id>`), avec tout son contenu, sous-dossiers compris | — |
| `password` | Mot de passe du lien, de 4 à 128 caractères. Il est haché, et jamais renvoyé. | aucun |
| `expiresAt` | Date d'expiration, dans le futur (ISO 8601) | aucune |
| `maxDownloads` | Nombre maximal de téléchargements | illimité |
| `recipients` | Adresses à qui envoyer le lien par email (20 au maximum) | `[]` |
| `message` | Message joint à l'email et affiché sur la page publique (2 000 caractères au maximum) | — |

```bash [Terminal]
curl -X POST https://cloud.exemple.com/api/shares \
  -H "Authorization: Bearer rca_…" \
  -H "X-Impersonate-User: alice@exemple.com" \
  -H "Content-Type: application/json" -H "Accept: application/json" \
  -d '{
    "file": "/api/files/01a0…",
    "expiresAt": "2026-10-31T18:00:00+01:00",
    "maxDownloads": 5,
    "recipients": ["client@exemple.com"],
    "message": "Voici le devis, comme convenu."
  }'
```

La réponse (`201`) :

```json
{
  "id": "01a1…",
  "token": "q3Zk…",
  "file": "/api/files/01a0…",
  "folder": null,
  "targetName": "Devis 2026-042.pdf",
  "expiresAt": "2026-10-31T17:00:00+00:00",
  "maxDownloads": 5,
  "downloadCount": 0,
  "passwordProtected": false,
  "recipients": ["client@exemple.com"],
  "message": "Voici le devis, comme convenu.",
  "notificationStatus": "queued",
  "createdAt": "2026-09-25T10:15:00+00:00",
  "lastDownloadAt": null
}
```

L'adresse publique du lien est `<adresse du front>/s/<token>`.

| Erreur | Cause |
|---|---|
| `422` | Ni `file` ni `folder`, ou les deux ; fichier ou dossier d'un autre utilisateur ; date passée ; mot de passe trop court ; adresse invalide ; plus de 20 destinataires |
| `403` | Application sans utilisateur (`X-Impersonate-User` manquant) |

### Notification par email

Avec des `recipients`, le worker envoie l'email par Rocket Mailer, au nom de l'utilisateur. `notificationStatus` suit l'envoi :

| `notificationStatus` | Signification |
|---|---|
| `null` | Aucun destinataire |
| `queued` | En attente du worker |
| `sent` | Accepté par Rocket Mailer |
| autre texte | L'erreur : Rocket Mailer non configuré, jeton refusé, utilisateur inconnu de Rocket Mailer… L'email n'est pas retenté. |

Voir [Notifications par email](/administration/storage#notifications-par-email).

## Lister et supprimer

| Requête | Effet |
|---|---|
| `GET /api/shares` | Liens de l'utilisateur, du plus récent au plus ancien. Filtres : `file=<id>`, `folder=<id>` |
| `GET /api/shares/{id}` | Un lien |
| `DELETE /api/shares/{id}` | Supprime le lien : il est aussitôt inutilisable (`204`) |

Un lien ne se modifie pas : supprimez-le et créez-en un autre. Supprimer un fichier ou un dossier supprime ses liens.

## Côté public

La page `/s/<token>` du front s'appuie sur deux endpoints **sans authentification** :

### Décrire le lien

```bash [Terminal]
curl https://cloud.exemple.com/api/public/shares/q3Zk… -H "Accept: application/json"
```

```json
{
  "name": "Devis 2026-042.pdf",
  "type": "file",
  "sharedBy": "Alice Durand",
  "message": "Voici le devis, comme convenu.",
  "expiresAt": "2026-10-31T17:00:00+00:00",
  "passwordProtected": false,
  "remainingDownloads": 5,
  "files": [
    { "id": "01a0…", "name": "Devis 2026-042.pdf", "size": 48213, "mimeType": "application/pdf" }
  ]
}
```

Pour un lien protégé, `files` est absent : le contenu n'est décrit qu'une fois le mot de passe vérifié.

### Télécharger

`POST /api/public/shares/{token}/download`, en formulaire (`multipart/form-data` ou `application/x-www-form-urlencoded`) :

| Champ | Rôle |
|---|---|
| `password` | Mot de passe, pour un lien protégé |
| `file` | Pour un dossier : identifiant du fichier à télécharger (requis) |
| `list` | `1` : renvoie la liste des fichiers (`{ "files": [...] }`) au lieu d'un fichier, après vérification du mot de passe |

```bash [Terminal]
curl -X POST https://cloud.exemple.com/api/public/shares/q3Zk…/download -o devis.pdf
```

Le fichier est toujours envoyé en téléchargement. Chaque téléchargement compte pour `maxDownloads` ; `list=1` ne compte pas. Le mot de passe passe dans le corps de la requête, jamais dans l'adresse.

| Code | Cause |
|---|---|
| `404` | Lien inconnu ou supprimé ; fichier absent du dossier partagé |
| `410` | Lien expiré, nombre de téléchargements atteint, ou propriétaire désactivé (`detail` donne la raison) |
| `403` | Mot de passe incorrect |
