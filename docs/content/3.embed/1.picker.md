Votre application peut afficher les dossiers et les fichiers Rocket Cloud de son utilisateur pour qu’il en **choisisse un** (un modèle à fusionner, une pièce jointe…) ou qu’il choisisse **un dossier** (où enregistrer un document). C’est ainsi que Rocket Dispatch propose sa bibliothèque de modèles Word.

Le sélecteur est une page de Rocket Cloud affichée dans une iframe : l’utilisateur voit ses fichiers sans quitter votre application, et votre application ne reçoit que **le fichier choisi** (identifiant, nom, type, taille). Elle lit ensuite son contenu côté serveur, avec son jeton d’application.

## 1. Déclarer l’application

Dans **Administration → Applications** de Rocket Cloud, créez l’application (ou reprenez-la) :

- cochez **Peut agir en tant qu’utilisateur** ;
- ajoutez l’**origine** de votre application dans les origines autorisées (`https://crm.exemple.com`, sans chemin) : seules ces pages peuvent afficher le sélecteur.

Notez son identifiant (UUID) et gardez son jeton `rca_…` sur votre serveur.

## 2. Délivrer un jeton d’intégration

Votre serveur échange son jeton d’application contre un **jeton d’intégration** de courte durée (15 minutes, `EMBED_TOKEN_TTL`), pour l’utilisateur connecté chez vous :

```bash [Terminal]
curl -X POST https://cloud.exemple.com/api/embed/token \
  -H "Authorization: Bearer rca_…" -H "X-Impersonate-User: alice@exemple.com" -H "Accept: application/json"
# → 201 { "token": "<jwt>", "applicationId": "0199…", "expiresAt": "…" }
```

Exposez-le à votre page par un endpoint à vous (par exemple `POST /rocket-cloud/token`), qui répond `{ "token": "…" }` pour **l’utilisateur de la session**, jamais pour un utilisateur passé par le navigateur. En mode suite, le jeton d’accès de Rocket Auth (identifiants client, audience `rocket-cloud`) remplace le jeton `rca_…`.

::warning
Le jeton `rca_…` ne doit jamais arriver dans le navigateur : seuls les jetons d’intégration y passent, et ils ne donnent accès qu’au sélecteur.
::

## 3. Afficher le sélecteur

### Web component

```html [page.html]
<script src="https://cloud.exemple.com/embed.js"></script>

<rocket-cloud-picker
  application-id="0199a1b2-7c3e-7d41-9f0a-4b2c6d8e1f23"
  token-url="/rocket-cloud/token"
  accept=".docx"
></rocket-cloud-picker>

<script>
  const picker = document.querySelector('rocket-cloud-picker')
  picker.addEventListener('select', (event) => {
    const { file } = event.detail   // { id, name, mimeType, size, sha256, folder, path, updatedAt }
    fetch('/modeles/choisir', { method: 'POST', body: JSON.stringify({ cloudFile: file.id }) })
  })
  picker.addEventListener('cancel', () => picker.hidden = true)
</script>
```

::field-group
  :::field{name="application-id" type="string" required}
  Identifiant (UUID) de l’application déclarée dans Rocket Cloud.
  :::

  :::field{name="token-url" type="string"}
  Votre endpoint de jeton, appelé en `POST` avec les cookies de votre site. Ou la propriété `getToken` (fonction qui renvoie une promesse du jeton).
  :::

  :::field{name="mode" type="file | folder"}
  `file` (par défaut) : choisir un fichier. `folder` : choisir un dossier, par exemple où enregistrer un document.
  :::

  :::field{name="accept" type="string"}
  Types acceptés, séparés par des virgules : types MIME (`application/pdf`), préfixes (`image/`) ou extensions courantes (`.docx`, `.xlsx`, `.pptx`, `.pdf`, `.odt`, `.txt`, `.csv`). Rocket Cloud détecte le type d’après le contenu, pas d’après le nom.
  :::

  :::field{name="folder" type="string"}
  Identifiant du dossier ouvert au départ (la racine sinon).
  :::

  :::field{name="base-url" type="string"}
  Adresse de Rocket Cloud ; par défaut, celle d’où `embed.js` est servi.
  :::

  :::field{name="min-height" type="number"}
  Hauteur minimale de l’iframe en pixels (360). La hauteur suit ensuite le contenu, sauf avec `no-auto-resize`.
  :::
::

Événements (qui remontent le DOM) : `ready`, `select` (`detail` : `{ file }` ou `{ folder }`), `cancel`, `error` (`detail` : l’erreur). Méthode `refresh()` : recharger le dossier affiché, par exemple après y avoir enregistré un fichier.

En mode `folder`, `detail.folder` vaut `{ id, name, path }` ; `id` est `null` pour la racine (« Mes fichiers »).

### JavaScript

```js [page.js]
const picker = RocketCloud.mount('#picker', {
  baseUrl: 'https://cloud.exemple.com',
  applicationId: '0199a1b2-7c3e-7d41-9f0a-4b2c6d8e1f23',
  getToken: () => fetch('/rocket-cloud/token', { method: 'POST' }).then(r => r.json()).then(d => d.token),
  mode: 'file',
  accept: ['.docx'],
  onSelect: ({ file }) => console.log(file),
  onCancel: () => picker.destroy(),
})
```

## 4. Lire ou enregistrer le fichier, côté serveur

Le sélecteur ne transmet que les métadonnées. Votre serveur lit le contenu, ou enregistre un nouveau document, au nom du même utilisateur :

```bash [Terminal]
# Lire le fichier choisi
curl -o modele.docx "https://cloud.exemple.com/api/files/<id>/content?download=1" \
  -H "Authorization: Bearer rca_…" -H "X-Impersonate-User: alice@exemple.com"

# Enregistrer un nouveau document dans le dossier choisi
curl -X POST https://cloud.exemple.com/api/files -H "Authorization: Bearer rca_…" -H "X-Impersonate-User: alice@exemple.com" \
  -H "Accept: application/json" -F file=@devis-martin.docx -F folder=<id du dossier>

# Mettre à jour ce document plus tard (même fichier)
curl -X PUT https://cloud.exemple.com/api/files/<id>/content -H "Authorization: Bearer rca_…" \
  -H "X-Impersonate-User: alice@exemple.com" --data-binary @devis-martin-v2.docx
```

Voir [Fichiers et dossiers](/api/files).

## Sécurité

- La page du sélecteur (`/embed/picker`) ne s’affiche que dans les origines autorisées de l’application (`Content-Security-Policy: frame-ancestors`) ; les autres pages de Rocket Cloud refusent toute iframe.
- Une session d’intégration **lit** : les dossiers, les fichiers, leur contenu et l’espace utilisé de son utilisateur. Elle ne peut ni déposer, ni renommer, ni supprimer, ni partager, ni appeler l’administration (`403`).
- Désactiver l’application, ou retirer son origine, arrête immédiatement les sélecteurs ouverts.

## Protocole

Pour une intégration sans `embed.js`, l’iframe `https://cloud.exemple.com/embed/picker?app=<application>&mode=file&accept=<types>&folder=<id>` échange des messages `postMessage` dont `source` vaut `rocket-cloud` :

| Sens | Message | Contenu |
|---|---|---|
| iframe → page | `ready`, `token-request` | La page répond `token` |
| page → iframe | `token` | `{ token }` |
| iframe → page | `loaded`, `resize` | `{ height }` |
| iframe → page | `selected` | `{ file }` ou `{ folder }` |
| iframe → page | `cancel` | — |
| page → iframe | `refresh` | Recharger le dossier |

Envoyez toujours vos messages à l’origine de Rocket Cloud (jamais `*`), et vérifiez `event.origin` des messages reçus.
