## Avec Docker Compose

::steps{level="3"}

### Démarrer la stack

```bash [Terminal]
docker compose up -d --build
```

Cela lance PostgreSQL, l'API (qui applique les migrations au démarrage), le worker et le front.

### Créer le compte administrateur

Ouvrez http://localhost:3200. Tant qu'aucun compte n'existe, Rocket Cloud affiche la page **Configuration initiale** : nom, email et mot de passe (12 caractères minimum) de l'administrateur. La page n'est plus jamais accessible ensuite.

::warning
Tant que le compte n'est pas créé, la première personne qui ouvre l'application peut le créer. Si l'instance est accessible par d'autres avant que vous la configuriez, définissez `SETUP_TOKEN` : la page demandera ce jeton.
::

Vous pouvez aussi créer l'administrateur en ligne de commande :

```bash [Terminal]
docker compose exec api php bin/console app:user:create admin@exemple.com 'un-mot-de-passe-long' --admin
```

### Régler le stockage et les notifications

Ajustez le quota et la taille maximale des fichiers, et reliez Rocket Cloud à Rocket Mailer pour envoyer les liens de partage par email. Voir [Stockage et notifications](/administration/storage).

::

| Adresse | Contenu |
|---|---|
| http://localhost:3200 | Application Rocket Cloud |
| http://localhost:8200/api/docs | Documentation OpenAPI de l'API |

## Images Docker

La CI publie deux images sur GitHub Container Registry, pour `main`, `develop` et les tags `vX.Y.Z` :

- `ghcr.io/fayouz/rocket-cloud-api` : API, et aussi le worker, avec la commande `php bin/console messenger:consume async scheduler_default` ;
- `ghcr.io/fayouz/rocket-cloud-front` : front Nuxt.

L'API et le worker partagent le dossier des données (`DATA_DIR`, volume `app_data`) : c'est là que sont stockés les fichiers. Sauvegardez-le avec la base de données.

## Configuration

### API

| Variable | Rôle | Défaut |
|---|---|---|
| `DATABASE_URL` | Connexion PostgreSQL | — |
| `APP_SECRET` | Secret Symfony | — |
| `JWT_PASSPHRASE` | Passphrase des clés JWT (`config/jwt/`, à monter en volume) | — |
| `MESSENGER_TRANSPORT_DSN` | File des tâches de fond (notifications de partage) | `doctrine://default` |
| `DATA_DIR` | Données de l'application : contenu des fichiers (`files/`) | `var/data` |
| `CLOUD_DEFAULT_QUOTA` | Espace disponible par utilisateur, en octets | `10737418240` (10 Go) |
| `CLOUD_MAX_FILE_SIZE` | Taille maximale d'un fichier, en octets. Au-delà de 512 Mo, augmentez aussi `upload_max_filesize` et `post_max_size` dans `docker/php.ini`. | `536870912` (512 Mo) |
| `FRONTEND_URL` | Adresse publique du front, pour les liens envoyés par email (`<FRONTEND_URL>/s/…`) | `http://localhost:3200` |
| `ROCKET_MAILER_URL`, `ROCKET_MAILER_TOKEN` | Rocket Mailer, pour envoyer les liens de partage par email. Vides : pas d'email. Voir [Notifications par email](/administration/storage#notifications-par-email). | — |
| `SECRETS_ENCRYPTION_KEY` | Clé de chiffrement des secrets en base (mot de passe de l'annuaire, secrets SSO). Vide : dérivée de `APP_SECRET`. La changer oblige à ressaisir les mots de passe. | — |
| `CORS_ALLOW_ORIGIN` | Origines autorisées à appeler l'API depuis un navigateur (regex) | localhost |
| `SETUP_TOKEN` | Jeton demandé par la page de configuration initiale | — |
| `UPDATE_REPOSITORY` | Dépôt GitHub dont les nouvelles versions sont signalées. Voir [Mises à jour](/administration/updates). | `fayouz/rocket-cloud` |
| `UPDATER_TOKEN` | Active la mise à jour en un clic, avec le service `updater` (profil `updater`) | — |
| `RUN_MIGRATIONS` | `1` pour appliquer les migrations au démarrage du conteneur | `0` |

Les variables LDAP sont décrites dans [Utilisateurs et LDAP](/administration/users-ldap).

### Autonome ou dans la suite Rocket

Par défaut, Rocket Cloud est **autonome** : il gère ses comptes (locaux, LDAP, fournisseurs OpenID Connect). Dans la **suite** Rocket, la connexion passe par Rocket Auth, qui gère aussi les utilisateurs, les groupes et l'annuaire :

| Variable | Rôle | Défaut |
|---|---|---|
| `ROCKET_AUTH_URL` | Adresse publique de Rocket Auth. Renseignée : mode suite. | — |
| `ROCKET_AUTH_INTERNAL_URL` | Adresse de Rocket Auth vue par l'API (ex. `http://auth-api` dans Docker) | l'adresse publique |
| `ROCKET_AUTH_CLIENT_ID`, `ROCKET_AUTH_CLIENT_SECRET` | Client OpenID Connect de Rocket Cloud, déclaré dans Rocket Auth | `rocket-cloud` |
| `ROCKET_AUTH_ADMIN_GROUP` | Groupe de Rocket Auth dont les membres administrent Rocket Cloud | `rocket-admins` |
| `ROCKET_LOCAL_LOGIN` | `1` : accès de secours par mot de passe local | `0` |

Voir le [README de rocket-core](https://github.com/fayouz/rocket-core#modes-autonome-et-suite).

### Tâches planifiées

Le worker (`messenger:consume async scheduler_default`) envoie les notifications de partage et vérifie lui-même, toutes les 5 minutes, l'annuaire, les fournisseurs SSO et Rocket Mailer.

Avec LDAP, planifiez aussi la synchronisation de l'annuaire :

```bash [crontab]
*/30 * * * *  docker compose exec -T api php bin/console app:ldap:sync
```

### Front

| Variable | Rôle |
|---|---|
| `NUXT_PUBLIC_API_BASE` | URL de l'API vue par le navigateur. **Vide** : le front relaie `/api` vers l'API (une seule URL publique, pas de CORS). |
| `NUXT_API_INTERNAL_BASE` | URL de l'API vue par le serveur du front, ex. `http://api:80` |
| `NUXT_PUBLIC_DOCS_URL`, `NUXT_PUBLIC_CHANGELOG_URL` | Liens « Documentation » et « Nouveautés » du tableau de bord |

::warning
En production, changez `APP_SECRET` et `JWT_PASSPHRASE`, montez les clés JWT dans un volume persistant et servez le front et l'API en **HTTPS** : les liens de partage et leurs mots de passe transitent par là.
::
